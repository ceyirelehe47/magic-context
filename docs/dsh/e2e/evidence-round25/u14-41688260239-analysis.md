`ctx_memory {action: write, content: "File relation: … (codeword FILE-HERON-2261)."}`
tool call (ordinal 11) and its result "Saved memory [ID: 12]" (ordinal 12);
fact 4's user message is ordinal 13. So ordinal 11 — inside [11, 15] — is the
agent's own tool call containing the codeword. The compartment title says
exactly that ("Persisted facts 3 and 4").

U14's "own codes" came from `factMessages` = message-history FTS rows, which
index user/assistant **text** only; tool-call inputs/results are not there, so
the checker could not see ordinal 11's codeword.

## Ruled out: historian restating `<project-memory>` (8a7864594)

At the time of both historian passes all four memories (ids 10–13) were active
(h-db-a1.json), so the historian's `<project-memory>` block carried all four
codes. If the historian had copied memory into summaries, [11, 15] would carry
ARCH/RULE and [1, 10] TODO, and the six later compartments would carry some
code. None does: each compartment carries exactly the codes of messages in its
range (counting tool calls). Classification: **possibility 2 (real messages in
range, correctly summarised); checker defect**. Not a product change.
