### Cause 1 — product (adapter parity): Magic's injected messages were history

On DSH the m0 knowledge baseline (`<session-history>` / `<project-memory>`)
and the `<ctx-search-hint>` are separate `magic-context`-sourced user messages
appended to the durable log. OpenCode/Pi add the same text at transform time
only, so their message store (source of core's message FTS index and of the
historian chunk) never holds it. The DSH history view
(`transcriptRawMessageProvider`) handed them to (a) the message-history index
(round 24a `4a586cb21`) — the `<project-memory>` block became one "message"
holding all four facts, every hint a "message" quoting a fact — and (b) the
historian, which wrote the injected memory into compartments of unrelated read
turns (32-34 above). That is why the paraphrase's top compartment was 32 and
why session A's history lanes duplicated every pinned fact.

Reproduced locally (`injected-history.test.ts`, before =
`r24c-injected-history-before.txt`): FTS rows 9/11/14 = the injected m0 and
hints; the historian chunk read through core `readSessionChunk` contains
`<project-memory>`. Fixed in `a529b7846` (after = `r24c-injected-history-after.txt`).

### Cause 2 — check script: the fact's message hit is folded into its compartment

Once round 24b (`f3d44e73b`) embedded compartments, core's
`mergeMessageAndCompartmentResults` (search.ts) folds every message hit that
lies inside a compartment returned by the semantic lane into that compartment
result (`match=hybrid`, `Snippet` = the message). U16 accepted only a bare
`ordinal=… role=user` line and took the fact's ordinal from that line, so it
found nothing although `[3]` (compartment 29, range 1-15, Snippet with the
codeword) IS the fact's own message (the four fact turns are ordinals 1-15; the
first read turn starts at 16). U18 used U16's ordinal → `factOrdinal: null`
although compartment 29 covering the fact was in its hits. U17 told the model
to expand the FIRST result; with RRF fusion of the semantic compartment lane
(rank of "file" in the read prompts under the bag-of-words mock) the fact's
compartment is not guaranteed rank 1 — rank 1 is not what U17 claims.

Fix `e5ce3b756` (no assertion relaxed): the fact's ordinal comes from session
A's message-history FTS rows (`ci-h.ts` `factMessages`), independent of the
search output; U16 accepts the bare ordinal line or the covering compartment
with the codeword in its Snippet; U17 asks the model to expand the result that
contains the codeword and now also requires the expanded range to cover the
fact ordinal; new guards: no injected block in any message result or in the
index (U16, U18), and no compartment before the search turn carries a codeword
its own messages do not (U14).
